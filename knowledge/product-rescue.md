# Product Rescue & Reliability

Product Rescue & Reliability is for unfinished, unstable, difficult-to-scale, insecure, delayed, or inherited software. ACEVA audits first rather than recommending a rebuild by reflex.

## Includes

- Code and architecture audit
- Bug stabilization and performance work
- AI-generated code review
- Security and deployment assessment
- Testing, documentation, and a modernization roadmap

The assessment identifies risks by severity and separates what can be kept from what should be replaced. A sample Rescue Report is described as containing findings, severity, what to keep, what to replace, and a 30/60/90-day plan.

ACEVA does not promise every product can be repaired and does not quote a rescue project before senior review.

## What a Rescue Report contains

Published on /services/rescue (verified 31 October 2026), the Rescue Report
provides:
- an executive diagnosis;
- an evidence-backed risk register;
- architecture and security findings;
- maintainability gaps;
- a keep / remediate / replace / defer matrix;
- a prioritized 30/60/90-day roadmap.

## How risks are ranked by severity in a technical audit

ACEVA audits first and lists the risks by severity. Each component is then
classified:
- **keep**: sound, so leave it and document it;
- **remediate**: fix it in place;
- **replace**: rebuild this part;
- **defer**: not now, revisit later.

The sample Rescue Report on ACEVA's Experiments page is a labelled sample
deliverable, not a client project. It shows the format. Each finding records:
- the area;
- what was found;
- a severity of Critical, High or Medium;
- a recommendation;
- the keep, remediate, replace or defer verdict.

The findings are then sequenced into a 30/60/90-day plan:
1. **First 30 days:** stop the bleeding.
2. **Days 30 to 60:** stabilize.
3. **Days 60 to 90:** modernize with intent.

The exact criteria used to assign a severity on a real engagement are not
published. The team confirms them through /contact.

## What a Product Rescue audit examines

The Rescue Sprint assesses architecture, code, dependencies, data, security,
testing and deployment. The service also covers AI-generated code review,
performance, and bug stabilization. ACEVA has not published which diagnostic
tools it uses; the team confirms that for a specific audit.

General practice, not a published ACEVA toolset. Common categories of
diagnostic tool are:
- static analysis and linting;
- dependency vulnerability scanners;
- test-coverage reports;
- performance profilers and database query analysis;
- error-monitoring and log review;
- a review of the hosting, CI and secrets configuration.
